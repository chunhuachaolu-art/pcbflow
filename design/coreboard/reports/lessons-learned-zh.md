# 经验总结 — STM32H743 核心板布线收尾与铺铜（2026-08-19）

> 本轮目标：自动收尾最后 11 个未布连接 + 铺铜。结局：**铺铜成功，自动收尾诚实失败**（7 轮尝试全部劣于基线），失败本身产出了完整的根因分析和可复用配方。以下按"下次怎么做"组织。

## 1. 最重要的教训：这是布局问题，不是布线问题

**现象**：Freerouting 全板优化后仍剩 11 个连接布不通，且集中在 U1↔U2 之间。

**根因（本轮实测）**：U1(LQFP176) 与 U2(TSOP-54) 的芯片间隙仅 **1.07mm**，而 FMC 总线约 45 个网络全部要从这个 21mm 宽的缝里穿过：
- 合法过孔中心窗口只有 y=48.925–48.995（**0.07mm 高**）
- U2 焊盘间 0.34mm 缝隙连 0.15mm 走线都过不去 → 每个顶排焊盘只有北面一个入口
- 总容量 ≈30 个通道 < 45 个需求 → **结构性饱和**

**下次怎么做**：
1. **布局阶段做"通道预算"**：两片总线器件对放时，间隙宽度 ≥ (需穿越网络数 × 0.35mm 车道间距) / 可用层数。本例 45×0.35/2 ≈ 7.9mm，实际 1.07mm——差 7 倍，布局时就该发现。
2. LQFP + TSOP 大总线对接的标准解法：间隙 ≥4mm 或错位摆放（扇出后再汇合），或改 BGA/更细间距封装配合大面积 fanout 区。
3. 自动布线器剩 >5% 连接布不完且都卡在同一区域时，先怀疑饱和，别急着换工具——换工具也解决不了容量问题。

## 2. 自动布线工具链经验（Freerouting 2.3.0）

| 经验 | 细节 |
|---|---|
| 增量重跑必劣化 | 在已布 DSN 上重跑 Freerouting 会拆掉自己布不回的扇出（16 断 vs 原 11 断） |
| 修改过的板导出 DSN 会让加载器卡死 | 脚本改过的板再导 DSN，Freerouting "Loading board file" 永久挂起（40min+ 空转 CPU）；原始板 DSN 53s 正常加载。原因未查明，绕过：只对原始状态跑 |
| SES 导入直写磁盘 | 之后 `save_board` 会误报"外部已修改"；用 `discard_or_reload` 重新同步 |
| 正确 CLI 参数 | `-de dsn -mp N -mt 1`；无 `-ao`；SES 自动生成在 DSN 旁边 |

## 3. 自研 A\* 路由器的得与失

**做对的部分**（0.1mm 网格、8 方向、过孔代价 80、同网铜不算障碍、岛分析）：
- **Minkowski 圆角膨胀**（而非方形切比雪夫膨胀）：方形膨胀在对角方向虚增 √2 倍阻塞区，曾把所有 LQFP 逃逸列误判为堵死——这是三个致命 bug 里最隐蔽的
- **线段-矩形相交必须含对角穿越判定**：只查端点在内/角点距离会漏掉斜穿走廊的线，留下"隐形墙"
- **确定性预放置优于搜索**：先按手算坐标放好关键过孔（焊盘对位），再让 A\* 只负责连线——贪婪顺序会互相饿死，确定性放置不会
- 孤立测试 10/11 布通证明**单连接能力没问题**

**做错的部分**：
- **层号映射 bug**：列表存层索引(0-3)、过滤键用层 ID(0/2/4/6)，内层拆线后列表不更新 → 连通性判断用了过期数据，"成功"是假的。教训：**簿记只有单一事实来源（文件），任何"内存态"结论落盘前都不算数**
- **0.1mm 网格 vs 0.07mm 合法带**：单元中心恰好在合法窗口外，过孔"永远放不进"——网格路由器要先算合法窗口内有没有单元中心
- **单格路径假成功**：起终点铜皮相距 <0.1mm 时 A\* 返回 1 格路径但没加任何铜；必须强制补 0.05mm 桥线并复查岛数

## 4. 验证方法论（本轮最大收获）

1. **连通性终审必须用 KiCad 自己的引擎**：`kicad-cli pcb drc --format json` 的 `unconnected_items` 计数，它理解填充多边形。自写检查器的三类误报：硬编码路径忽略参数、不解析 zone 填充（GND 永远显示 61 岛）、桥线端点 0.0024mm 级失配误报断裂
2. **对副本跑 DRC 会套默认规则**：`.kicad_pcb` 副本离开 `.kicad_pro` 后 min track 变 0.2，凭空多出 89~199 个线宽违规。DRC 必须在工程目录里跑
3. **验证分层**：几何合法性（DRC）≠ 连通性（unconnected）≠ 功能正确（哪些网断更重要——电源断 > 总线断 > 外设断）

## 5. 环境/工具坑（KiCad 10.0.5 便携版 + SWIG）

- **层常量非教科书值**：F_Cu=0、B_Cu=2、In1=4、In2=6（跟文件层表序）。写脚本先 `int(pcbnew.In1_Cu)` 验证
- **SWIG 句柄随机损坏**：Remove()/Add() 序列后 `GetTracks()` 抛 `'SwigPyObject' object is not iterable`、`FindNet()` 返回坏对象，重试无效且永久。对策：网络码从焊盘一次性取（`pad.GetNetCode()`），铜皮列表增量维护、永不重扫
- **MCP 缝合过孔工具在高密度板上会卡死整个服务**（简单调用也 30s 超时），只能杀进程恢复
- **无头铺铜可用**：`kicad-cli pcb drc --refill-zones --save-board` 干净可靠，本板把 GND 未连接从 60 修到 23
- 30s MCP 超时不等于失败（常在后台完成），先验证再重试，盲目重试会重复执行

## 6. 决策经验

- **设止损线**：本轮 7 轮尝试若在 v4（26 断）后就用"功能账"对比（电源断 > 外设断）做终审，能省 2 轮。终审指标应该是"断的网是什么"而不只是"断了几个"
- **零风险增量优先**：v7 的"只摘无附带损伤的果子"思路正确（电源网优先），执行败于簿记 bug——思路与实现要分开评价
- **给用户的选择要带数据**：本轮向用户提供的"基线副本 + 继续理由 + 价格影响为零"三件套让决策没有摩擦
